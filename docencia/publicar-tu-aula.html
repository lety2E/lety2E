Publicar tu aula

Parte 2 de 2. Tu aula ya existe en tu computadora; ahora la subimos a internet con GitHub. Sirve igual en Mac que en Windows.

¿Aún no la armas? Empieza por la parte 1: Abrir tu aula.

La idea: se prepara una sola vez, y de ahí en adelante tú cambias lo que quieras con tu agente y cuando esté listo le dices «súbelo». Él se encarga de subirlo a internet. La preparación toma una sesión; la haces con tu agente, que te va guiando.

1

La cuenta de GitHub

¿Ya la creaste de tarea? Pasa al paso 2. Este paso es tuyo, no del agente: la cuenta lleva tu correo y tu contraseña. Entra a github.com y crea una cuenta. Piensa bien el nombre de usuario: va a ser la dirección de tu aula. Si te llamas MateConAna, tu página será mateconana.github.io.

Si el nombre que querías ya está ocupado, pruébale una variante; es normal.

Solo crea la cuenta. Al terminar, GitHub te va a ofrecer crear cosas nuevas: no le muevas. El espacio donde vivirá tu aula (se llama repositorio) lo crea tu agente en el paso 4.

2

Las dos herramientas del agente

Para subir tu aula, el agente usa dos programas: Git (guarda las versiones) y GitHub CLI (habla con tu cuenta). Pídele que revise si ya los tienes y que te diga cómo instalar lo que falte.

«Quiero que tú te encargues de subir mi aula a GitHub. Revisa si en esta computadora tengo Git y GitHub CLI (gh). Si falta alguno, guíame paso a paso para instalarlo; yo le doy clic a lo que haga falta.»

  • En Windows: se instalan con sus instaladores normales (git-scm.com y cli.github.com), dándole Siguiente a todo.
  • En Mac: Git viene con las «herramientas de desarrollador» de Apple; el agente te dirá cómo pedirlas. GitHub CLI se baja de cli.github.com (el instalador .pkg).

En Mac: si la instalación de las herramientas de Apple falla, no es tu computadora: a veces el servidor de Apple está caído. Inténtalo otro día, o usa el plan B de abajo mientras tanto.

3

Conecta a tu agente con tu cuenta (una sola vez)

El agente te va a dar un código de 8 letras y abrirá tu navegador en GitHub. Tú entras con tu cuenta, pegas el código y autorizas. Tu contraseña la escribes tú en GitHub, nunca en el chat.

«Conéctate a mi cuenta de GitHub con gh auth login, por el navegador, y deja Git configurado para usar esa sesión.»

4

Tu agente publica tu aula

«Crea el repositorio público tuusuario.github.io con lo que hay en esta carpeta y súbelo, para que mi aula quede en https://tuusuario.github.io»

En unos minutos tu aula está en tuusuario.github.io (tu usuario, en minúsculas). Tiene que ser público para que la página sea gratis.

En Mac: si sale un aviso de que no se puede acceder a la carpeta del Escritorio, dale Permitir. Si ya le diste «No permitir», se arregla en Configuración del Sistema → Privacidad y seguridad → Archivos y carpetas.

5

Que se quede como regla

Para que tu agente lo recuerde siempre, pídele que lo anote en su manual:

«Anota en el CLAUDE.md: cuando yo diga «súbelo», guardas los cambios con una descripción corta en español, los subes a GitHub y me confirmas cuando la página ya esté actualizada. Nunca subas nada sin que yo lo pida.»

Plan B: GitHub Desktop

Si en tu computadora no se pudo instalar Git o GitHub CLI, puedes subir tu aula tú misma con GitHub Desktop (desktop.github.com), un programa con botones que no necesita nada más.

  1. En Mac: mueve la app a Aplicaciones antes de abrirla.
  2. Inicia sesión, luego File → Add Local Repository… → tu carpeta → Create Repository.
  3. Publish repository con el nombre tuusuario.github.io y desmarcando Keep this code private.
  4. Para cada cambio: escribe qué cambió en Summary, Commit to main y luego Push origin.

Cuando ya funcionen Git y GitHub CLI, tu agente puede tomar la estafeta desde el paso 3.

De aquí en adelante

  1. Pídele al agente el cambio que quieras.
  2. Revísalo en tu computadora (doble clic en index.html).
  3. Cuando te guste, dile: «súbelo».
  4. Espera de 1 a 3 minutos y recarga tu página.
